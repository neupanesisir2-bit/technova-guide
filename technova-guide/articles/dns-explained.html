DNS explained: how domain names find websites

5 min read · Beginner guide · Updated November 17, 2026

People remember names more easily than numbers. You can type a domain such as example.com into a browser, but computers use IP addresses to route traffic. The Domain Name System (DNS) helps translate human-friendly domain names into the records needed to reach internet services.

Think of DNS as an internet directory

Imagine looking up a business name in a directory to find its phone number. DNS performs a related task for domain names. It is a distributed, hierarchical naming system, not one giant list stored on a single server.

What happens during a typical lookup?

  1. Browser and operating system checks: The device may already have a cached answer from a previous lookup.
  2. Recursive resolver: If needed, the device asks a configured DNS resolver to find the answer.
  3. Root and top-level domain servers: The resolver can follow referrals through the DNS hierarchy, such as from the root to the relevant top-level domain.
  4. Authoritative nameserver: The resolver asks the domain's authoritative server for the requested record.
  5. Answer returned: The resolver sends the result back to the device and may cache it according to its TTL.

Common DNS record types

  • A: Maps a hostname to an IPv4 address.
  • AAAA: Maps a hostname to an IPv6 address.
  • CNAME: Makes one name an alias of another name.
  • MX: Identifies mail servers for a domain.
  • TXT: Stores text data often used for domain verification and email authentication.
  • NS: Identifies authoritative nameservers for a zone.

What is DNS caching and TTL?

Resolvers and devices can cache DNS answers to reduce repeated lookups. A record's Time to Live (TTL) tells caches how long the record may be retained. This is why DNS changes do not always appear everywhere immediately: different caches may still hold earlier answers until their TTL expires.

Is DNS the same as a web server?

No. DNS helps a client discover where a service is located. The browser then connects to the relevant server using the appropriate protocol, such as HTTPS. DNS resolution is one part of loading a website, not the whole process.

Try this: On many systems, nslookup example.com or dig example.com can show DNS query results. Availability and command options vary by operating system.

Final thoughts

DNS is one of the internet's essential building blocks. Understanding resolvers, authoritative servers, records and caching makes troubleshooting domain and connectivity issues much easier.
